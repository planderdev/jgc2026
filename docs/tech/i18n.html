영문판

/en/ 페이지가 만들어지는 방식과, 한국어를 고친 뒤 영문판을 맞추는 절차입니다.

#구조

  • en/ 아래 페이지는 생성물입니다. scripts/build-en.mjs가 한국어 HTML을 원본으로 lang=en, 영문 title/description, 절대경로 링크를 넣어 만듭니다.

  • 본문·폼·메시지·토스트는 assets/js/i18n.en.js의 한→영 사전(330여 문구 + 정규식 패턴)이 런타임에 바꿉니다(MutationObserver). 같은 JS·데이터를 쓰므로 한국어 기능 변경이 자동 반영됩니다.

  • DB에는 항상 한국어 기관명이 저장됩니다(화면 표시만 번역). 관리자·기관 화면은 한국어 그대로입니다.

  • 헤더 KR | EN 스위치는 같은 페이지의 다른 언어로 이동합니다. canonical + hreflang(ko/en/x-default)을 양방향으로 넣고, sitemap에 ko+en URL이 있습니다.

#한국어 페이지를 고친 뒤

node scripts/build-en.mjs
node scripts/set-share-urls.mjs https://2026jejugcf.com

자동 점검이 "영문판(en/)이 한국어 원본과 일치하는지"를 검사하므로, 빼먹으면 커밋에 ✗가 붙고 위 명령이 메시지에 나옵니다.

#새 문구를 넣었을 때

assets/js/i18n.en.js의 D에 '한국어': 'English'를 추가합니다. 숫자·이름이 섞인 문장은 R의 정규식으로. 빠진 문구는 npm run qa의 "EN 페이지에 한글 없음" 검사(17페이지 + 예약 플로우 상태)가 잡습니다.

#영문명 검토 필요

기관·기업 영문명은 공식 표기가 확인된 곳(KB Investment, Lotte Ventures, Y&Archer, Jeju Contents Agency 등) 외에는 로마자 표기입니다. 기관 확인 후 사전에서 고치세요. 정책 문서 영문은 참고용이며 한국어 원문이 기준입니다.
